# Taste — Coding

## Verification & Delivery Discipline

- Treats a strict gate set as the definition of "done" before declaring work complete: `cargo fmt --check`, `cargo clippy -D warnings` (all targets, all features), the full workspace test suite (with test counts reported), rustdoc with `-D warnings`, and the project's own self-audit binary. Confidence: 0.8
- Keeps the committed `Cargo.lock` untouched in the final diff: temporary local workarounds to unblock a broken toolchain (e.g., pinning a transitive build-dep like `cc 1.1.0` when the locked version is incompatible with the local rustc) are reverted before finishing. Confidence: 0.7
- When asked to install/validate the product, exercises every public interface the way a real consumer would — a compiled C program against the actual `cdylib`, a maturin wheel installed in a clean venv, a full MCP stdio protocol session, real-GPU CUDA tests, and the project's own stress/acceptance harness — not just `cargo test`. Confidence: 0.7
- Treats the project's own scripts and harnesses as in-scope deliverables: bugs found in them while testing (e.g., an unquoted `env RUSTDOCFLAGS=-D warnings` assignment splitting the value) are fixed, not worked around. Confidence: 0.6
- Follows a design-then-implement flow for features: proposes the component structure (new scripts, flags, docs) and matches the project's existing script conventions (set -euo pipefail, cd to repo root, full French header comment, --help via sed over the header) before writing code. Confidence: 0.7
- Writes shell scripts defensively: guards every argument-parsing case with an explicit `shift`, avoids bare `cmd &&` under `set -e` (uses `if`), treats a present-but-broken CLI binary (e.g., incomplete npm install of `claude`) as a detectable failure with a clear message and non-zero exit, and keeps read-only/detect operations usable even on a dirty tree. Confidence: 0.6
- Makes best-effort integrations non-blocking: agent auto-registration may fail (broken `claude` binary, no agent found) but the main installation must still succeed with an explicit warning — then proves both the success and failure paths with mocks (fake `claude` binary) and simulated environments. Confidence: 0.6

## Defensive Coding & API Design

- Fixes security defects by validating external input before trusting it (registry lookup before pointer deref, explicit size/length bounds before launches, file-size caps and regular-file checks before reads) rather than by documentation-only hardening. Confidence: 0.7
- Prefers adding fallible/validated variants alongside existing APIs over breaking public API: `try_from_projection_with` / `try_score` / `validate_codec` added while keeping panicking wrappers for compatibility. Confidence: 0.6
- Fixes security advisories pragmatically: upgrades the dependency to the version that closes the actually-relevant vulnerability (e.g., pyo3 0.23 → 0.24 fixing RUSTSEC-2025-0020), verifies the remaining advisories do not apply to the APIs in use, documents the decision and the tracked future upgrade in a code comment, and moves on rather than forcing a risky multi-major upgrade. Confidence: 0.7
- Writes code that is lint-clean across toolchains, not just the locally pinned one: replacing `% align == 0` with `.is_multiple_of()` after a newer rustc's clippy flagged `manual_is_multiple_of` (with a comment noting the stabilized version satisfies the MSRV) instead of adding per-toolchain `#[allow]`s. Confidence: 0.6
- Adds regression/parity/security tests alongside every fix (codec parity tests vs the reference, double-release and forged-handle tests, overflow tests), and rejects behavior that silently degrades (unknown codec flags must error, not fall through). GPU↔CPU parity tests on real hardware exposed a scoring bug (max_abs 6–16 → ~1e-6 after the fix). Confidence: 0.8
- Keeps documentation and claims truthful: replaces stale counts and overclaims ("property/fuzz" → "property-based", "prompt-injection detection" → "geometric outlier filter with uncalibrated thresholds"). Confidence: 0.7
- Treats documentation updates as a required, non-optional part of feature delivery — explicitly emphasized when requesting the augmented installer ("met a jour la documentation c'est important"): a dedicated doc (docs/AUTO_INSTALL.md), README installation section, and cross-referenced links (docs/MCP.md) all updated and checked for consistency. Confidence: 0.8
- Values honesty about infeasible approaches: a prior experimental path (round-trip llama.cpp integration) is expected to be treated as a measured NO-GO (ΔPPL +40%) and not silently re-attempted — the user's demand to "wire it up" is answered with an architecture plan that reconciles the request with the documented evidence rather than pretending the failed approach is viable. Confidence: 0.8
- Distrusts suspiciously-perfect results: when the fused-QK run returned PPL identical to baseline, verified the mechanism actually executed (opt-in diagnostics, log lines, per-pass timing) instead of trusting the number — this exposed two silent no-ops (flash attention bypassing the custom node; the fused node never scheduled) that the too-good result had masked, and the fix was validated by a re-measurement. Confidence: 0.6
- Regenerates patches from the real `git diff` of an edited clone rather than hand-writing diff hunks: a hand-written hunk with miscounted line numbers failed strict `git apply`, while regenerating from the actual diff applied cleanly with `fuzz=0`. Confidence: 0.5
- Splits large work into logical commits by theme (audit remediation / installer / LLM integration) rather than one giant commit, and excludes pre-existing unrelated working-tree changes (e.g., a `.gitattributes` edit and whitespace-only patch from before the session) from those commits — asking the user to confirm the splitting/push strategy before acting on a remote-visible action. Confidence: 0.7

## Performance-Critical Code

- Eliminates asymptotic hot-path waste (O(n²) per-step scans, per-free full sorts, per-dim recomputed scales) by maintaining O(1) counters and hoisting loop-invariant computation into registers/buffers. Confidence: 0.6

## Git Workflow & Conflict Resolution

- Prefers merging upstream into an active PR branch over rebasing when upstream has advanced: merge preserves history, resolves conflicts once, and avoids rewriting pushed commits (no force-push) — chosen explicitly after a rebase attempt churned the branch (abort left HEAD on master with the branch's commits dangling as orphans). Confidence: 0.9
- Triages each conflict file individually after inspecting what each side actually changed (`git show`/`git diff`, comparing test sets with `comm`): takes upstream wholesale when it has superseded the branch's work (dropping the now-obsolete code and patches, e.g., fused-QK mode and the C-ABI handle registry superseded by master's API), merges both sides when complementary (e.g., keep the branch's `validate_codec`/`try_score` + upstream's SIMD score path), and keeps the branch's work when upstream lacks it (module split, porting upstream's SAFETY comments into it). Confidence: 0.7
- Documents every conflict-resolution decision explicitly in the merge commit message: a structured "Conflict resolution:" section listing each file and the take-ours / take-theirs / merge-both choice, plus the verified gates (test count, clippy, fmt). Confidence: 0.6
- When the locally pinned toolchain is too old to evaluate a lint (e.g., `clippy::manual_is_multiple_of` unknown on 1.89), validates the gates with the CI-equivalent stable toolchain rather than treating the unknown lint as an error — and conforms to upstream's stricter lint gates during merges (adding SAFETY comments demanded by upstream's `#![deny(clippy::undocumented_unsafe_blocks)]`) instead of suppressing them. Confidence: 0.6
